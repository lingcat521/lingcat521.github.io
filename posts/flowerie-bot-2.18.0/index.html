🌸 花璃 v2.18.0 更新公告

承接 v2.17.0——这次不铺新能力，回头把「怎么说话」重做了一遍。

之前有四套拆句机制叠在一起（AI 多条 JSON / 边界切分 / 按空格切 / 流式）， 互相打架还经常把话切碎。这次全部收敛成一套规则，顺手删掉两套没人用的。

✂️ 一、分句只剩三条规则

  1. 总长 超过 100 字：整条发，不拆
  2. 不到 40 字：按空格和句末标点拆
  3. 中间：整条发

逗号、顿号、小数点、括号不再当切点。之前 3.5 会被切成 3. 和 5， （气鼓鼓） 也会被切出来单独成句——很蠢，改掉了。

一次最多拆 3 句，多出来的进缓存，隔 4~6 秒补发。防刷屏，但不丢内容。

🎭 二、表情包三条通道

之前只能靠模型在回复里写 [STICKER:文件名]，而且分句关掉时这个标记会原样发给用户—— 群里见过 [STICKER:7N07_偷看.gif] 这种鬼东西，就是这么漏出去的。

现在标记在解析层就被剥离，跟分句开关彻底无关。文本一条、图片一条，分开发。

三条通道，各自开关：

  • 文本标记：模型自己写 [STICKER:xxx]
  • 概率附图：被 @ 或叫名字时，10% 概率补一张随机图
  • 工具调用：sticker_search 搜、sticker_send 发，模型自己决定

（「自动化」页新增 AI_STICKER_ENABLED）

GIF 保留动图。之前我把 GIF 转成静态 PNG 是判断错了——官方接口其实吃 GIF， 实测 639KB 的动图能正常发出去；真被拒了才降级成首帧 PNG。

索引也修了：并发（默认 4 路）+ 批量上限，几百张表情包不用一次跑完。 描述从 25 字短句改成正经的 80~150 字（外观 / 动作 / 表情 / 适用场景）。

👁️ 三、识图：主模型能自己看就别绕路

VISION_ROUTE_MODE 三档：

  • auto —— 主模型在白名单里就自己看，不在就调外部识图模型
  • external —— 永远走外部
  • native —— 强制主模型直看

实测推理型模型单图要吃 500~3000 reasoning tokens，所以直看有独立预算 VISION_CHAT_MAX_TOKENS，不跟聊天的 DEEPSEEK_MAX_TOKENS 抢额度。

另外纯图片消息（没有文字）默认只识图记上下文、不触发回复—— 之前每张图都要回一句，群里太吵了。

🗑️ 四、删掉的两套机制

  • 流式回复：框架本身不支持 SSE 增量发送，留着是死代码
  • AI 自主多条（{"messages":[...]}）：和分句功能重复，语义还打架

配置键一起删了（STREAM_REPLY_ / MULTI_REPLY_）。 .env 里还留着的话启动时会跳过，不报错。

🔧 五、顺带修的

  • @ 召唤绕过节流：之前连续回 3 条就把群封 60 秒。你在群里喊她完全没反应，

就是撞上这个了。现在被 @ 或直接回复消息不受连回上限约束，只有自发接话才限流

  • 接话概率 REPLY_PROBABILITY：官方机器人只收 @ 消息，桥接器得给每条都注入 @，

所以必须有个概率门才能限频

  • 配置读取：从 settings.db 读（db > .env > 代码默认）。长驻看守进程持着旧

shell 函数会一直用旧环境变量拉子进程——改配置请走 Web UI 或数据库

🔌 六、协议层没动

OneBot11 / Milky 的适配层和传输层一行没改。发图还是标准 image 段 + file:// 绝对路径，NapCat 原生支持。

唯一注意：换回 NapCat 时把 MENTION_REPLY_GATE_ENABLED 关掉（默认就是关）， 真实 @ 才能必回。

🧪 七、测试

  • 新增解析层矩阵测试：分句开/关 × 有/无标记 六种组合，验证「文本与图片分开且标记不外发」
  • 拆出 multimodal.py（多模态加载）与 reply_guard.py（图片跳过 / @门 / 召唤判定），

守住 ai_client 430 行、message_router 650 行的防上帝类上限

  • 2556 passed / 157 skipped（本地全量；perl 插件在 Termux 编译超时是环境老问题）
