🌸 花璃 v2.19.3 更新公告

承接 v2.19.2——这轮给搜索装了个会自己花钱的引擎，顺便把「愿不愿意花这个钱」的决定权交回你手上。

🔍 一、搜索多了一条路：让模型自己去搜

之前四个引擎都是花璃抓 HTML 自己解析——DuckDuckGo、Bing、SearXNG，免费但经常被反爬。

这次接的是完全不同的机制：搜索在 DeepSeek 服务端执行。花璃只发一个「请搜索 X」的请求， 模型在云端自己调搜索工具，把结构化结果连文本一起返回：

POST {端点}/messages
{
  "model": "deepseek-v4-flash",
  "messages": [{"role": "user", "content": "Perform a web search for the query: ..."}],
  "tools": [{"type": "web_search_20250305", "name": "web_search", "max_uses": 3}],
  "thinking": {"type": "disabled"}        ← 搜索不需要推理，省 token
}

解析这块有个坑值得说：结果项本身通常不带摘要，只有 url 和标题。 摘要在 text 块的 citations[].cited_text 里，得按 url 建映射才能补齐。 照搬了 DeepSeek Harness 的实现思路，实测能用：

引擎: deepseek-native
- DeepSeek V4 双版本正式上线，采用华为昇腾芯片
- DeepSeek V4 成本暴降 73%…

顺带一个原则：没有结果块就直接报错，不降级去正则刮正文。刮出来的东西没法保证是搜索结果。

💸 二、两个开关，别搞混

这是我想了半天才拆清楚的：

| 开关 | 管什么 | 关掉会怎样 | | :--- | :--- | :--- | | SEARCH_PAID_ENABLED | 允不允许花钱（总闸） | 把 deepseek-native 从执行链里彻底剔除，就算你手动写进 SEARCH_ENGINES 也不用 | | SEARCH_DEEPSEEK_PRIORITY | 允许之后，要不要排第一 | 不自动前置，但配置里写了它还是会用 |

一句话：PAID 是「能不能用」，PRIORITY 是「排不排前面」。

我一开始只做了 PRIORITY，后来发现不对劲——那只能控制顺序，管不住「到底允不允许花这个钱」。 加完 PAID 才算真的把闸门装上了。

还有个细节：.env 里留着 sk-original 这种模板值，会被识别成「未配置」。 不然链路每次都要先去打一个必然 401 的端点，白白慢一秒。

🤔 三、让 AI 自己决定用哪条路

配了可用 Key 之后，web_search 工具会多一个可选参数：

{"query": "DeepSeek V4 发布时间", "engine": "deepseek-native"}   # 要准确，愿意花钱
{"query": "今天天气", "engine": "bing"}                          # 省着点
{"query": "Python 3.14 新特性"}                                  # 不传，宿主自己挑

工具描述里直接写了取舍，模型自己权衡：

deepseek-native（走模型服务端搜索，结果更准且有摘要，但较慢且按 token 计费） 或免费引擎 ddg/bing/searxng（快、免费、可能被反爬）。 不确定时不要传，宿主会按配置自动挑。

两个刻意设计的地方：

  1. 没配 Key 时根本不暴露这个参数——免费引擎之间（ddg / bing / searxng）的差别对模型没有决策意义，

让它纠结用哪个纯属浪费 token，交给自动回退就够了

  1. 模型传了不存在的引擎名，静默忽略——不返回错误。不然它会看到报错然后重试，把对话上下文打乱

🖥️ 四、搜索页重做了一遍

这轮交给 6.2sol 做 UI，我给了它一份很长的提示词（包括「不许动这几个文件」和「必须跑全量测试」）。

结果意外地守规矩：18 个改动文件全在允许范围内，四个禁改文件一个字没动。

现在的搜索页：

  • 顶部一行说清「为什么这么搜」：实际执行顺序 + 编排原因
  • 引擎卡片分五种状态：付费关闭 / Key 缺失 / 模板值 / 可用 / 冷却中

（之前全显示成红叉，根本分不清是没配还是挂了）

  • 试搜可以指定引擎，页面显示实际命中的是哪个
  • 逐引擎自检显示耗时与预算——原生搜索要 30 秒级别，不能按免费引擎的秒级预算判它超时

用户状态页也加了一张卡，但它是省钱版：

点「连通性测试」时：
  不带 tools        ← 不触发真实搜索
  max_tokens: 16   ← 只验端点活着
  超时 20 秒        ← 这是模型回合，比别的 ping 慢

结果文案会写「未消耗搜索额度」。401 和 404 分开报——一个是 Key 不对，一个是端点路径配错， 这两个用户能自己修，但得先知道是哪种。

🐛 五、顺手修的

  • 占位符黑名单太宽：原来有 sk-xxx，结果任何含连续 x 的真 key 都被误判成模板值。删了
  • 一个测试写死了「引擎数量 = 4」，加新引擎就挂。改成按语义断言
  • 6.2sol 改了一行测试地址（example.com → IP 字面量），因为它那边解析不了 DNS。

我验证本机和 CI 都能解析，把改动还原了——保留原测试对 DNS 解析路径的覆盖
