🌸 花璃 v2.3.0 更新公告

诶嘿w，这次不是维护性更新啦——花璃迎来了一个功能版本，而且是一个有点不一样的版本喵。

从这一版开始，花璃的定位会写得更清楚一点：它是一个以 QQ Bot 为原生场景的跨语言插件平台。 QQ 群聊机器人是它最顺手的用法，但它的本体其实是"插件平台"：一套语言无关的插件协议、五套官方 SDK、 插件之间可以互相调用、插件可以自带管理页面。

（所以这次的公告会比上次长一点点……毕竟攒了好几个大件uwu）

🧰 一、五套官方 SDK：插件不再只有 Python

以前写插件基本只能用 Python（或者自己照协议手搓）。现在仓库里有五套官方 SDK：

  • Python（内置 runner，写完即跑）
  • TypeScript / Go / Rust / Java（各自独立，零第三方依赖：TS 不要 npm 包、Go 只用标准库、Rust 不用 crate、Java 只用 JDK）

五套 SDK 的能力是对齐的：上下文、配置、权限查询、存储、事件、WebUI、插件间通信，一共 14 项能力， 不是"某个语言有、别的语言没有"。

而且这次不是"代码写好了"就算数——每种语言都真写了一个最小插件，在 CI 里真编译、真启动、真调用、真关闭：

  • 最小插件测试：46 条，五种语言全部真跑（不是 skip、不是 mock）
  • 覆盖 Build / Load / Ready / Ping / Info / Echo / Event / Call / Error / Permission / Shutdown 十一行
  • 跨语言链路实测：Python→Go、TS→Java、TS→TS、Python→TS、Go→Rust、Rust→Java

（想抄骨架的话直接看 examples/multilang-sdk/，五个语言各一份，能跑）

🔗 二、插件之间可以互相调用了

这是这一版最大的新能力：插件不再只能跟 Core 说话，还能调用别的插件。

  • 统一抽象：plugin.call(target, method, params) / plugin.emit(name, payload) / plugin.on(name, handler)
  • 五种语言写法不同，语义完全一致（Python/TS/Go/Rust/Java 都有）
  • 跨语言请求一律经 Core Router（插件之间不能私自开 TCP/HTTP 绕过权限）
  • 权限沿用原有系统：plugin.call.<目标> 或更细的 plugin.call.<目标>.<方法>，管理员批准才生效
  • 超时、取消、事件广播、错误码（12 个，跨语言原样保留）
  • 调用链带 trace_id / call_id / hop_count：A→B→A→B 这种回环会被环保护拦住，不会打到天荒地老
  • 目标可以是"某个插件的任意健康实例"，也可以是 plugin.a#instance1 这样指定实例

（简单说：以后可以让"翻译插件"调用"词典插件"，让"统计插件"调用"抽卡插件"，语言不同也没关系喵）

🖥️ 三、插件可以自带管理页面了（Plugin WebUI）

插件现在能提供自己的网页：webui.page / webui.action / webui.asset 三个协议方法， 页面、动作、静态资源都由插件决定，路由、权限、净化、隔离由引擎负责。

  • 零 JavaScript：和花璃主站一样，页面只有 HTML + CSS + 表单，关掉 JS 照样能用
  • 六项 webui.* 权限：页面、动作、配置读写、存储读写，分开批准
  • 静态资源（webui/static/）与插件动态资源（webui.asset）两条通道
  • 文件上传 / 下载走插件自己的空间，webui.files 权限单独把关

这一版还补上了真浏览器端到端测试：CI 里装真 Chromium，真的打开页面、真的点提交， 断言 document.title / 插件名 / 状态 / 设置表单 / 跨插件调用面板 —— 21 条全过。

（所以"插件页面能打开"这件事，现在是浏览器自己说的，不是我们说的 uwu）

🔒 四、安全与隔离（这次的测试比较狠）

给插件 WebUI 补了一批"打自己"的测试，全部真服务器 + 真插件进程：

  • 路径穿越：../、../../、/etc/passwd、编码、双重编码、反斜杠、绝对路径、符号链接 —— 全部拒绝
  • 跨插件隔离：A 的页面 / CSS / 配置 / 上传 / 下载 / 会话，B 和 C 都拿不到
  • Secret 泄漏：HTML / CSS / JSON / 错误响应里扫描哨兵值，0 命中
  • XSS / HTML 注入 / 模板注入：按零 JS 策略转义或拒绝
  • 结构化错误：目标不存在、方法不存在、超时、插件内部报错、权限被拒，页面显示的是

Status: Failed + Code: <错误码>，不是 500，也不会把堆栈和路径吐出来

🔢 五、版本号终于规范了

之前 2.2.2 之后的版本号是 2.2.22 / 2.2.222 / 2.2.2222 / 2.2.22222（当时随手加 2 加的……）， 不符合语义化版本。这次按 SemVer 重编：

  • 2.2.22 → 2.2.3、2.2.222 → 2.2.4、2.2.2222 → 2.2.5、2.2.22222 → 2.2.6
  • GitHub Release 的 tag 与标题同步更名（资产内容不变，之前下载的包还是同一个包）
  • 本版是 2.3.0（新增功能 → MINOR 版本）

（以后不会再出现"后面越长越多 2"这种事了，我保证.jpg）

📚 六、文档重写：不看源码也能写插件

顺手把文档整个过了一遍：

  • 改掉过时的徽章、测试数、版本号、功能清单；删掉重复和失效的内容
  • 插件开发指南重写：manifest 全字段、五语言 API 对照、权限全表、存储与配置、

Plugin WebUI、插件间通信、错误码与调试、打包与安装、13 种语言最小实现清单

  • 目标很明确：让写插件的人不用看源码，照着文档就能把插件写出来

📦 七、下载与升级

  • 各平台资产（Windows / Linux / macOS，x64 与 arm64）在

Release 页面 下载

  • 安装说明：Windows ·

  • 升级：替换程序文件即可，插件与数据目录（plugins/、data/）保持不动

🐛 八、已知问题（诚实版）

  • QQ / P2P 实机链路：当前开发环境没有真实 QQ / NapCat / OneBot 实机，

这部分一直是 BLOCKED（不是"通过"，也不是"看起来能用"），实机用例在 CI 里 skip 并打印缺失条件

  • 插件页面还没有 <title>：插件页是面板壳的片段，浏览器标签页标题目前由页面内的大标题承担
  • 模板变量不能放在标签属性位置：<input ... {{ x_checked }}> 这种写法会被净化器丢掉（已知限制，插件改用 class 表达状态）
  • 取消是"尽可能停止"：同步阻塞中的 handler 没法被强制打断，CANCEL 会在它返回后生效

（这些都在文档里写清楚了，不藏着）

🌸 最后总结

这次的 v2.3.0 是把"插件平台"这件事真正立起来的一版：

  • 插件可以用五种语言写，且有官方 SDK 与真跑测试
  • 插件之间可以互相调用（跨语言经 Core Router，权限和安全一个都没少）
  • 插件可以自带管理页面（零 JS，真浏览器测过）
  • 版本号规范化、文档重写、仓库定位改成了"以 QQ Bot 为原生场景的跨语言插件平台"

QQ 机器人的部分也没落下：人设对话、识图、记忆、人格、表情包、MCP、主动聊天都照旧， 只是从这一版开始，花璃不只是一个 bot，也是一个可以被你写插件改造的平台。

感谢一直以来使用花璃、写插件、提问题和看公告的大家！

—— 花璃 v2.3.0 🌸
