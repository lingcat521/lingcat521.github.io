🌸 花璃 v2.7.0 更新公告

呜……这次是一封道歉信（划掉）修复公告。

v2.6.0 加了「长回复切分」和「流式回复」，听起来很美好——

但花璃自己复盘的时候发现，这两个功能埋了一堆坑。

于是就有了 v2.7.0：把 v2.6.0 的两份审计（8 个语义冲突 + 9 个链路断联）全部修掉， 外加一个新能力——本机自建模型也可以接进来啦。

🐛 一、修掉的离谱 Bug（挑严重的说）

「分段回复」会把群聊静默 60 秒

以前花璃发分段消息时，每发一段就被记一次「连续回复」。 连发 3 段后——群被强制冷却 60 秒，你发的下一句话直接被吞掉。

（对，就是那种「花璃说完话你发消息没反应」的灵异事件，找到原因了.jpg）

现在一轮分段只计一次，不会再吞消息了。

「记忆指令」会被直接发到群里

花璃有个内部机制：模型输出的 MEMORY_JSON: 行本来是要被剥掉、存进记忆库的。 但流式模式绕过了这道处理—— 结果就是记忆指令原样发到群里，而且长期记忆也跟着失效。

（想象一下你偷偷写日记结果日记本被当众念出来……现在修好了）

流式模式的花璃「没有人设」

流式路径悄悄绕过了人格注入——流式模式下的花璃收到的 prompt 里： 没有人设、没有群梗、没有花语记忆、没有群昵称，连熔断器都没有。

（简单说就是开了流式之后花璃会「失忆 + 变成另一个人」）

现在流式和整轮走的是同一套注入链，人格、群梗、花语、熔断全部对齐。

「流式」其实根本不是流式

v2.6.0 的流式实现是：等全部生成完，再分段发出去。 省下来的「首句早到时间」被完全浪费掉了，和普通模式没有区别。

现在是真的边生成边发，段到了就先发。 半路失败也只会补记账，不会把整段重新发一遍（避免刷屏）。

🔧 二、其它修复（快进模式）

  • 段长默认从 40 提到 200：以前 40 字上限和人设的「15～20 字短句」叠加，切分功能基本永远不触发
  • 上限串线修复：切分和 AI 多条回复的上限以前会互相串线，现在各归各
  • 分段立即发送：以前分段还要等 1.5～4 秒随机间隔，8 段话要等半分钟
  • 表情包标记只看第一段：[STICKER:] 出现在第 2 段会被当正文发出去，现在逐段识别
  • 流式空产出不再重发：以前流式返回空还会再跑一整轮请求（双倍预算）
  • 流式失败双扣预算：新增预算回退

🏠 三、新能力：接入本机自建模型

如果你在本机跑 Ollama / llama.cpp / vLLM 之类的模型服务，现在可以不填 API Key直接接入。

规则很简单：

  • 地址指向 127.0.0.1 / localhost / ::1 → Key 可以留空
  • 地址指向第三方厂商或局域网 → 照样要填 Key

（局域网不放行是因为局域网服务通常有密码，花璃不想自作主张）

开通后：

  • 请求不会发送 Authorization 头（以前空 Key 会发出一个非法的「Bearer …」，看着就难受）
  • Web UI 状态页会显示「本机回环 · 免密钥」，不会再误报「未配置 Key」
  • 聊天、流式、识图、引战检测全部覆盖

开关 AI_ALLOW_LOOPBACK_NO_KEY=true（默认开），设 false 可以恢复严格模式。

🧪 四、怎么验证的

  • CI 三档全绿（Python 3.9 / 3.12 + PostgreSQL + 37 项验收）
  • ruff 全绿
  • 本地全量 2494 个测试通过（0 失败）
  • 行数护栏：message_router.py 650 行上限仍然守住了

（修复一共碰了 40 多个文件，但默认行为只放宽不收紧——升级不会改变现有配置的效果）

🌸 最后总结

v2.7.0 做的事情：

  1. 把 v2.6.0 的坑填平（17 个审计项全部修复）
  2. 让花璃能接本机模型（免 Key）

如果 v2.6.0 让你体验到了什么奇怪行为（吞消息 / 记忆泄漏 / 流式没人设）， 升级到 v2.7.0 就好啦。

新能力默认就是开的（回环地址才生效，局域网不放心）， 不想用设 AI_ALLOW_LOOPBACK_NO_KEY=false 就回到严格模式。

QQ 机器人的部分照旧：人设对话、识图、记忆、人格、表情包、主动聊天都没动， 插件协议、权限语义、AI 预算与重试也都保持原样。

感谢一直在用花璃、写插件、提问题和看公告的大家！

花璃还在运行，项目也还在慢慢变好喵。

—— 花璃 v2.7.0 🌸
