🌸 花璃 v2.6.0 更新公告

锵锵——花璃更新啦！

这次是一个功能版本。主要解决了一件从诞生以来就存在的小别扭：

花璃说话被 40 字上限截断，还要加上「...」

以前的花璃说到一半就会被掐断（呜呜），这次终于可以好好把话说完了喵。

✂️ 一、长回复不再被截断

以前如果花璃想说的话超过 40 个字，会被直接砍掉并补上「...」，像这样：

今天天气真不错 我们出去玩吧 记得带伞喔 别忘了带水壶...

（话说一半被掐住真的很痛苦诶）

现在新增了「边界感知切分」，超过长度的回复会按照这个顺序找切点：

换行 → 句尾标点 → 逗号 → 空格 → 硬切

然后把长文本切成多条独立消息依次发送，内容零丢失，不再有「...」。

  • 开关：SPLIT_REPLY_ENABLED=false（默认关，旧行为完全不变）
  • 单条段长上限：SPLIT_REPLY_SEGMENT_LIMIT
  • 最大条数：SPLIT_REPLY_MAX_MESSAGES（防止刷屏）

（默认是关着的哦，想用的话在 .env 或 Web UI 里打开就行）

🌊 二、流式回复（边生成边发）

以前花璃回复的时候，要先等整段全部生成完，才能发出消息。

现在新增了流式模式：模型那边还在生成，花璃这边已经可以一句一句往外发了。

  • 内部用 SSE 增量 + 句子缓冲（攒够一句再发，不会刷出单词碎片）
  • 开关：STREAM_REPLY_ENABLED=false（默认关）
  • 需要你的模型服务支持 SSE

（简单说就是——花璃说话变快了，不用再傻等了喵）

🧩 三、插件系统新能力

给写插件的朋友们带了两个小礼物：

  • split_reply 动作：插件可以调用花璃的边界感知切分（bot.split_reply(text, limit)）
  • ai_stream 升级：以前是「整轮拿完再假装切片」，现在是真正的 SSE 流式了

权限方面 split_reply 归入 read_message（纯本地操作，不碰发消息），保持最小授权。

⚙️ 四、三个入口都能配

新配置在三个地方都能改，不用翻代码：

  • .env 手写
  • Web UI 配置页（热更新，改完立刻生效）
  • 首次启动自动生成的配置模板

🧪 五、测试与护栏

  • 新增 32 个单元测试
  • message_router.py 控制在 650 行以内（防上帝类回归，超过会报错）
  • 本地 + CI 全量回归，ruff 全绿

（该说不说，这次为了把行数压回 650，把流式编排放进了独立模块，反而更清楚了）

🌸 最后总结

v2.6.0 主要做了两件事：

  1. 让花璃把话说完（边界感知切分）
  2. 让花璃说得更快（流式分句）

全部默认关闭，升级之后行为和以前一模一样；想用的话一个开关就能打开。

QQ 机器人的部分照旧：人设对话、识图、记忆、人格、表情包、主动聊天都没动， 插件协议、权限语义、AI 预算与重试也都保持原样。

感谢一直在用花璃、写插件、提问题和看公告的大家！

花璃还在运行，项目也还在慢慢变好喵。

—— 花璃 v2.6.0 🌸
